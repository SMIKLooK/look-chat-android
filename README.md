# Look Chat — голосовой ассистент с вшитым ИИ-движком

Мини-чат и голосовой ассистент на Kotlin (Jetpack Compose, Material 3).
Бекенд вшит в приложение: запросы к моделям уходят напрямую в API
провайдеров (Gemini, OpenRouter, GPTunneL), пакет `ai/`.
Каждый запрос уходит к модели сам по себе, без истории переписки:
модель не помнит предыдущих сообщений, поэтому вопросы вроде
«а теперь короче» не сработают.
Пишете вопрос текстом или говорите голосом — приложение разбирает его,
выбирает провайдера и показывает ответ модели прямо в чате, голосом
или текстом.
Ошибки выводятся как сообщения с красным фоном с машиночитаемым кодом,
у ответов модели подпись: имя модели, провайдер и время обработки.

Скриншоты (сняты на эмуляторе) — в папке [screenshots/](screenshots/).

## Голосовой ассистент

Кнопка 🎙 в шапке включает ассистента — дальше можно не трогать телефон:

- работает **в фоне** через foreground-сервис с постоянным уведомлением
  («Look Ассистент — Слушаю кодовое слово „старт"»); приложение можно
  свернуть, сервис продолжит слушать;
- непрерывно распознаёт речь (офлайн-движок, ru-RU) и ждёт
  слово **«старт»** — фразы без него игнорируются;
- «старт гемини расскажи анекдот» → в движок уходит
  «gemini расскажи анекдот» (русские названия моделей нормализуются:
  гемини/джемини → gemini, дипсик → deepseek); кодовое слово в запрос
  не отправляется;
- если модель не назвали («старт какая погода») — подставляется фри;
- **ответ приходит текстом в чат и озвучивается голосом** (системный TTS,
  русский голос); пока ассистент говорит, микрофон приостановлен;
- **тап по строке статуса («🔊 Отвечаю голосом…») останавливает озвучку**;
- **кодовое слово настраивается** в настройках (⚙): по умолчанию «старт»,
  можно любое своё (например «джарвис»). Оно нужно только для старта
  записи — в запрос не попадает, там формат «<модель> <запрос>»;
  текст уведомления сразу показывает актуальное слово;
- **диктовка завершается тремя способами**: слово окончания (по умолчанию
  «стоп», настраивается), **пауза 3,5 секунды** после последней речи — запрос
  уйдёт сам, или пустое слово окончания — отправка по каждой паузе;
  кодовое слово ловится уже на недоговорённой фразе, без ожидания тишины;
  слово окончания тоже проверяется на частичном тексте;
- **символы, которые не озвучивать** (⚙): эти символы вырезаются из
  ответа перед TTS. По умолчанию `*_#~`` ` (markdown), можно дописать
  любые — например эмодзи;
- уведомление ассистента **живое**: показывает актуальное состояние —
  «Слушаю кодовое слово…» → «Записываю…» → «Отправляю запрос…» →
  «Отвечаю голосом…» → снова «Слушаю…»;
- боковое меню (☰) — **список всех ИИ движка**: подключённые провайдеры,
  модели и псевдонимы, тап по названию подставляет модель в поле ввода;
- в боковом меню можно **задать свои слова для моделей** («дип сик» →
  deepseek, «фри» → openrouter/free — что угодно): работают и в тексте,
  и голосом; встроенные фразы: «дип сик»/«депп сик»/«деп сик» → deepseek,
  «фри»/«free» → free-модель OpenRouter (алиас движка);
- распознавание — **офлайн-движок Vosk** (русская модель vosk-model-small-ru
  вшита в приложение, ~46 МБ): аудио читается напрямую через AudioRecord,
  без системного SpeechRecognizer и его лимита сессий, поэтому ассистент
  не «умирает» после нескольких запросов и одинаково работает в фоне,
  с выключенным экраном и без интернета;
- сервис держит wakelock, чтобы CPU не засыпал, пока ассистент слушает
  с выключенным экраном (на агрессивных прошивках всё равно отключите
  оптимизацию батареи);
- вручную набранные запросы при включённом ассистенте тоже озвучиваются.

В строке быстрых подсказок первыми стоят главные модели:
`deepseek`, `gemini`, `фри`, затем остальные бесплатные
(инклинг, немотрон‑ультра/супер/лайт/омни, гемма, лагуна, норд‑код,
линг, ликвид, квэн, дотс и т.д. — алиасы вшиты в приложение).
Видны только модели тех провайдеров, чьи ключи заданы (свои — в ⚙,
встроенные — в `ai/Keys.kt`).
Алиасы резолвятся встроенным реестром (`ai/ModelAliases.kt` +
`Keys.ExtraModelAliases`); приложение пересылает слово как есть, а для
моделей с дефисом («немотрон-ультра») знает фразовые варианты без
дефиса — так их слышит распознавание.

Разрешения запрашиваются при первом включении: микрофон и уведомления.
Для надёжной работы в фоне на MIUI/Huawei и т.п. стоит отключить
оптимизацию батареи для приложения. Распознавание полностью офлайн
(модель вшита в APK), поэтому Google-сервисы речи не нужны.

## Возможности

- чат: история сообщений, индикатор «Думаю…», автопрокрутка; сообщения
  пользователя — справа, ответы — слева;
- ответы моделей отображаются с разметкой: жирный/курсив, `код`,
  списки, заголовки, код-блоки; у каждого сообщения показывается время;
- запрос можно отменить, пока висит «Думаю…»: кнопка «Отправить»
  превращается в «стоп» и обрывает запрос вместе с ожиданием;
- автопрокрутка не утаскивает из истории: пока листаешь вверх, новые
  сообщения не двигают список — вернуться к последнему можно круглой
  кнопкой «↓»;
- руками можно писать просто вопрос без ключевого слова — модель
  подставится сама (фри); формат «старт <модель> <запрос>» тоже работает;
- подсказки моделей — вшиты в приложение (реестр провайдеров + алиасы):
  тап по чипу подставляет модель в поле ввода;
- кодовые слова ассистента меняются в приложении (шестерёнка в шапке)
  и сохраняются; уведомление ассистента показывает актуальное кодовое
  слово и обновляется сразу после смены;
- долгое нажатие на сообщение копирует его текст (с вибрацией; на
  Android 13+ подтверждение показывает сама система);
- клавиша Enter на клавиатуре = «Отправить».

## Где взять APK

Готовые APK в репозиторий не попадают (`.gitignore`) — соберите их сами:

- **`./gradlew assembleRelease` — APK для телефона (~62 МБ).** R8-минификация,
  сжатие ресурсов, только arm64-v8a и armeabi-v7a. Подписан debug-ключом,
  поэтому ставится без Google Play. Если будешь разбирать краши — приложи
  `app/build/outputs/mapping/release/mapping.txt`, им расшифровываются стектрейсы.
- **`./gradlew assembleDebug` — APK для разработки (~103 МБ).** Без минификации,
  со всеми ABI (ставится и на эмулятор x86_64).

Результат появится в `app/build/outputs/apk/<вариант>/`.

Модель Vosk (~48 МБ) вшита в оба APK и распаковывается на устройстве
при первом включении ассистента.

## Как расширять

Типовые задачи и то, где одна точка входа:

- **Новая модель/псевдоним** — `ai/ModelAliases.kt` (или `Keys.ExtraModelAliases`,
  чтобы не трогать встроенный список); закрепить в первых чипах — одна
  строка в `logic/RequestText.kt` → `PINNED_MODELS` (+ тест).
- **Новый провайдер** — класс в `ai/` с интерфейсом `AiProvider`
  (как `OpenRouterProvider`): адрес API, `supports()`, `complete()`;
  регистрация — в `LocalBackend.defaultRegistry()`.
- **Голосовое название модели** — фразовые псевдонимы в
  `logic/RequestText.kt` → `PHRASE_ALIASES` (для названий с дефисом —
  вариант без дефиса, как его слышит Vosk).
- **Новая настройка** — свойство в `data/Settings.kt` → поток в
  `AssistantEngine` → ветка в `saveSettings` → поле в
  `SettingsDialog` (`ui/SettingsDialog.kt`). Тесты: `SettingsTest` +
  `AssistantEngineTest.saveSettings…`.
- **Новое правило разбора речи** — в `logic/VoiceCommandParser.kt`
  (чистые функции без Android, тестируются мгновенно).
- **Новая подготовка текста к озвучке** — `logic/SpeechText.kt`.
- **Новое правило markdown-разметки** — разбор в `logic/MarkdownParser.kt`
  (+ тест), рендер — в `ui/MarkdownText.kt`.
- **Новый сценарий диктовки** — только `voice/VoiceSessionManager.kt`;
  движок не знает деталей, ему приходит готовый текст.

Правило слоёв (проверено тестами и импортами): `logic` и `data` ничего
не знают о проекте, `voice` ходит только в них, `ai` (движок) —
самостоятельный слой без Android-зависимостей, UI и сервис — только в
`AssistantEngine`. Нарушать направление нельзя — иначе потеряется
тестируемость без эмулятора.

## Как вписать ключи провайдеров

Проще всего — прямо в приложении: ⚙ → раздел **«API-ключи
провайдеров»**. Впиши свой ключ (Gemini, OpenRouter, Gptunnel) и нажми
«Сохранить» — провайдер подключится сразу, без пересборки. Свой ключ
перекрывает встроенный, пустое поле возвращает встроенный. Ключи
хранятся только в SharedPreferences на телефоне. Поля ключей скрыты —
показать можно иконкой глаза. В шапке чата и в боковом меню 🔑
помечает провайдера, который работает на твоём ключе.

Встроенные ключи для сборки задаются в файле
`app/src/main/java/com/look/chat/ai/Keys.kt`. Сам `Keys.kt` в git не
попадает (он в `.gitignore`) — после клонирования репозитория скопируй
шаблон и впиши ключи:

```bash
cp app/src/main/java/com/look/chat/ai/Keys.kt.example \
   app/src/main/java/com/look/chat/ai/Keys.kt
```

Провайдер без ключа просто не подключается, остальные работают:

```kotlin
var Gemini = "AIza…"        // https://aistudio.google.com/apikey
var OpenRouter = "sk-or-…"   // https://openrouter.ai/keys
var Gptunnel = ""            // https://gptunnel.ru (личный кабинет)
```

Если меняешь встроенные ключи — пересоберите APK. Нюансы:

- **Приватность**: встроенные ключи вшиваются в APK — не публикуйте
  собранный `Keys.kt` и не отдавайте APK с ключами кому попало. Свои
  ключи из настроек в APK не попадают.
- Если ключей нет вообще, чипы моделей пусты, а на любой запрос придёт
  красное сообщение с подсказкой открыть настройки (⚙).

Быстро перекинуть APK на телефон без Telegram: в папке
`/home/look/lookchat-share` лежит APK, и по Wi-Fi он отдаётся сервером
`http://192.168.0.16:8000/LookChat-debug.apk` — откройте эту ссылку в
браузере телефона и скачайте (сервер запускается командой
`python3 -m http.server 8000 --directory /home/look/lookchat-share`,
остановить: `pkill -f "http.server 8000"`).

Весь трафик — https к API провайдеров: Gemini, OpenRouter, GPTunneL.
Распознавание речи полностью офлайн (Vosk).

## Сборка из командной строки

```bash
./gradlew assembleDebug     # debug-APK
./gradlew assembleRelease   # release-APK (подписан debug-ключом)
```

Нужен JDK 17+ и Android SDK (platform 36, build-tools 36). В Android Studio
достаточно открыть папку проекта — `local.properties` студия создаст сама.

## Тесты

Проект покрыт юнит-тестами (200, JVM, без эмулятора):

```bash
./gradlew testDebugUnitTest          # все тесты
./gradlew testDebugUnitTest --tests "com.look.chat.logic.*"   # только логика
```

Отчёт: `app/build/reports/tests/testDebugUnitTest/index.html`.

Что покрыто:

- **`logic/` — чистая логика команд** (быстрые JVM-тесты):
  `RequestText` — псевдонимы моделей (включая фразовые «дип сик»,
  «немотрон ультра»), сборка «<модель> <запрос>», свои слова (транслит
  и опечатки), список подсказок; `VoiceCommand` — кодовое слово и слово
  окончания с прощением описок; `SpeechText` — вырезание символов перед
  озвучкой и нарезка длинных ответов; `MarkdownParser` — разбор ответов
  моделей для рендера в чате; `TimeFormat` — время сообщения «14:05»;
- **`ai/` — вшитый движок** (JVM-тесты, MockWebServer для HTTP):
  `RequestParser` — формат «<модель> <запрос>» (включая «модель:запрос»);
  `ProviderRegistry` — псевдонимы, приоритет провайдеров, неизвестная
  модель; `OpenRouter`/`Gptunnel` — OpenAI-совместимый чат, слаги,
  WAF-403; `Gemini` — generateContent, blockReason, роли; `LocalBackend`
  — сквозной разбор → провайдер, реестр из `Keys.kt` и своих ключей
  из настроек;
- **`data/`**: `Settings` — хранение настроек (Robolectric);
- **`AssistantEngine`** (Robolectric): сохранение настроек, ошибки
  движка, отмена запроса в полёте, сквозные сценарии чата с фейковым
  провайдером;
- **`voice/`**: машина состояний диктовки `VoiceSessionManager` (кодовое
  слово → подтверждение → запись → «стоп»/тишина → команда), таймер
  сигнала «я работаю» `BeepGenerator`, контракт `TtsSpeaker` без аудио.

Не покрыто юнит-тестами (нужен реальный девайс — стоит проверить руками
или добавить instrumented-тесты): микрофонный поток `MicListener`
(нативный Vosk), живой TTS, `AssistantService` (foreground-сервис),
Compose-экран.

## Структура

```
app/src/main/java/com/look/chat/
  LookApp.kt                 Application: ранняя инициализация движка
  AssistantEngine.kt         фасад: состояние (StateFlow), запросы, координация
  service/
    AssistantService.kt      foreground-сервис ассистента (уведомление, wakelock)
  voice/
    VoiceSessionManager.kt   машина состояний диктовки (кодовое слово → запрос)
    audio/
      MicListener.kt         непрерывное офлайн-распознавание (Vosk)
      BeepGenerator.kt       сигнал «я работаю»
      TtsSpeaker.kt          озвучка ответов (системный TTS)
  logic/
    RequestText.kt           псевдонимы моделей, сборка запроса
    VoiceCommandParser.kt    кодовое слово, слово окончания, разбор фразы
    SpeechText.kt            подготовка текста к озвучке
    MarkdownParser.kt        разбор markdown-ответов моделей для рендера
    TimeFormat.kt            время сообщения («14:05»)
    TextMatcher.kt           нормализация, транслит, сравнение с опечатками
    ModelSuggestions.kt      список моделей для подсказок и меню
  ui/
    ChatScreen.kt            адаптер UI: подписки на движок → состояние экрана
    MainActivity.kt           точка входа (ComponentActivity + Compose)
    ChatScreenContent.kt     вёрстка экрана (stateless, с @Preview)
    MarkdownText.kt          рендер разобранного markdown-ответа
    SettingsDialog.kt        диалог настроек
    ModelsDrawerSheet.kt     боковое меню: модели и свои слова
    theme/Theme.kt           тема (динамические цвета Material You)
  ai/
    Keys.kt                  API-ключи провайдеров (в git не попадает)
    Keys.kt.example          шаблон Keys.kt для свежего клона
    LocalBackend.kt          вшитый бекенд: разбор → провайдер → ответ
    RequestParser.kt         формат «<модель> <запрос>»
    ModelAliases.kt          встроенные псевдонимы моделей
    ProviderRegistry.kt      реестр провайдеров + алиасы, выбор провайдера

    Http.kt                  общий HTTP-слой + формат /chat/completions
    OpenRouterProvider.kt    провайдер OpenRouter (агрегатор, free-модели)
    GptunnelProvider.kt      провайдер GPTunneL (агрегатор в рублях)
    GeminiProvider.kt        провайдер Google Gemini (generateContent)
  data/
    Settings.kt              SharedPreferences-настройки
    model/
      ChatMessage.kt         сообщение чата
      ModelState.kt          подсказки моделей
app/src/test/java/com/look/chat/
  AssistantEngineTest.kt     фасад: настройки, чат, движок (Robolectric)
  ai/…Test.kt                движок: парсер, реестр, провайдеры (MockWebServer)
  voice/…Test.kt             диктовка, сигнал, TTS-контракт
  logic/…Test.kt             тесты чистой логики (JVM)
  data/…Test.kt              тесты настроек (Robolectric)
```

Формат запроса вшитого движка: `"<модель> <запрос>"` (или
`"<модель>: <запрос>"`) → ответ модели + имя провайдера и время
обработки. Приложение само подставляет модель, если её не назвали, и
прогоняет русские псевдонимы («гемини» → gemini и т.п.).
